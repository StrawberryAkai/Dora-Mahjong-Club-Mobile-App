# Dora Helper

Flutter / Dart 编写的 Android、iOS 四人立直麻将记分应用。v0.1 包含固定房间、成员搜索与创建、东南西北入座、最终点数录入、自动完成、历史记录和独立管理入口。

产品名称为 **Dora Helper**，服务于 **Dora Mahjong Club（UCSD 麻将社）**。首版版本记法 `0.1.0.1` 对应 Flutter `0.1.0+1`，即版本 `0.1.0`、构建号 `1`。Android 应用标识为 `dora.dora_mahjong`；iOS 因不支持下划线，使用 `dora.doraMahjong`。这些是项目中的发布配置，尚不代表已在应用商店注册或发布。

当前版本为 `0.1.1+2`。手机返回键会逐级返回应用内上一页，有弹窗时先关闭弹窗；首页没有上一页时保持打开。

开发者接手请先阅读 [开发维护指南](MAINTAINING.md)，了解代码入口、同步流程、积分与座位约束，以及 Git Bash 预览命令。

## 先体验，不需要数据库

默认 `APP_MODE=local`，使用**本设备上的演示数据**，不连接 Supabase，行为与原来的 `demo` 模式相同。数据库尚未建立时即可体验完整流程。已有本地数据继续保留，不会上传，也不会在日后自动迁移到 Supabase。

需要 Flutter stable（当前验证环境为 Flutter 3.47.5 / Dart 3.13.4）。

```powershell
Copy-Item .env.example .env
flutter pub get
flutter run
```

如果本机 Flutter 尚未加入 PATH，本次工作目录已准备了忽略版本控制的 SDK，可使用：

```powershell
.\.tools\flutter\bin\flutter.bat pub get
.\.tools\flutter\bin\flutter.bat run -d chrome
```

Chrome 仅作开发预览，发布目标仍为 Android / iOS。Windows 当前未安装 Android SDK；原生 Android 编译需要先安装 Android Studio 与 SDK。iOS 构建需要 macOS、Xcode 及相应签名配置。

演示路线：

1. 搜索 `A`，选择 `Andy`，进入房间首页。
2. `7699` 为空房间，`9162` 有四人和一场待完成对局。
3. 进入 `9162` 的录分页面。Andy 是创建者，可以代填北位 Xiong 的成绩。
4. 填 `15000`，四人成绩合计 100,000，整场自动完成。
5. 查看「记录」中分开的「我参与的」与「俱乐部」列表；创建者可以更正整场成绩。
6. 切换至 Amy 或创建新名字，可体验空房间入座。管理员演示入口可体验改名与清理座位。

演示管理入口明确标记为体验功能，不代表真实管理员认证。正式模式必须用自己设置的管理员账号密码。

成员入口默认不展示名单，输入姓名首字后才显示匹配成员。点击主页右上角头像，在个人面板使用语言与明暗图标切换中英文／深浅色。选择保存在本设备，重新打开或切换成员后仍会保留。

个人面板并排显示累计 PT 和当前 MMR。「排行榜」可切换 MMR / PT，展示俱乐部普通成员；「活动」使用卡片展示活动，进入详情后可查看该活动的 PT 榜单并切换其他活动。管理员可以创建和编辑活动；成员开局时可选择当前房间正在进行的活动，或保持普通对局。

总排行榜每批展示 50 人，向下滚动继续加载，并按需绘制可见行。可搜索中英文姓名，搜索结果保留真实总榜名次；当前成员姓名旁显示“我”，进入排行榜时自动定位到本人所在行，必要时展开至所在批次。当前分页基于已经取得的数据快照，尚未增加服务端分页。

MMR、PT 和活动榜单采用连续并列排名：同分同名次，下一档积分的名次只加 1，例如 `40、40、40、41`。排名按完整榜单计算，搜索与分页不会重新编号；导入数据中的旧名次不覆盖当前榜单。

## 接入 Supabase

请按 [Supabase 配置与管理员说明](docs/supabase-setup.md) 操作。应用迁移前先核对目标数据库已有的表、RPC 和迁移记录；已有数据的项目不能直接重跑初始化脚本。开发维护约束见 [开发维护指南](MAINTAINING.md)。

将 `.env` 中的配置改为：

```dotenv
APP_MODE=development
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_PUBLIC_KEY
```

启用 Supabase 匿名登录，让普通成员无密码选择姓名；独立管理员通过用户名和密码登录。管理员不是普通成员，不进入名字提示和座位名单。

`APP_MODE` 仅支持 `local` 和 `development`；后者连接上述 Supabase 项目。移动端 `.env` 会随应用打包，**只放公开连接配置**。高权限密钥、管理员密码不放入其中，真实 `.env` 已被 Git 忽略。切换模式后重新运行／构建应用。

## 座位在线状态

普通成员退出账号时，未开局的座位立即释放；若正在对局，则保留座位，结束或取消对局后清理离线成员的座位，对局及成绩记录保留。

未开局时，已选择身份的成员或管理员可点击其他玩家的座位，在弹出菜单中选择红色「移除玩家」。此操作仅清理该玩家在当前房间的座位；对局开始后禁止移除。服务端规则位于 `supabase/migrations/202609230003_remove_seated_player.sql`。

正式模式使用每 15 秒续期、有效期 60 秒的座位租约。关闭页面时尽力发送释放请求；强制关闭或断网时，由超时兜底。后台暂停续期，短暂失去焦点不影响续期。超时座位会在下一次刷新、心跳或入座操作时清理，通常为约 60 秒加刷新间隔，并非独立定时任务。每次入座绑定当前客户端，旧客户端不能释放新客户端的座位。本地模式持久化待离座状态，重启后也会清理遗留座位。

需要应用 `supabase/migrations/202609230002_seat_presence.sql` 后再运行新版客户端；该迁移保留现有快照与积分逻辑。

## 计分规则

- 每人起始 25,000 点；最终点数允许负数，必须是 100 的倍数。
- 单人成绩先保存；四份成绩齐全且合计为 100,000 时自动完成。
- 总分错误时显示实际合计和差额，保持待纠错状态。
- 界面名次同分按本场起始座位东、南、西、北排序；积分马点按同分所占顺位平分。
- 单场 PT 为 `(最终点数 - 25000) / 1000 + 实际马点`；新成员 MMR 为 1500。
- 已结算对局合并展示场内名次、原始点数、MMR／累计 PT、本场变化及俱乐部排名升降；技术结算字段保留在数据中。
- 创建者／管理员可以代填或更正；完成后的更正以整场保存，并记录前后成绩。
- 更正不要求原因，取消未完成对局必须填写原因。

PT/MMR 使用修正版 `riichi-pt-mmr-v1`。演示模式在 Dart 本地结算，正式模式由服务端在同一事务完成对局、保存明细和更新 MMR；重复请求不会重复加分。更正会按原结算顺序重放历史，覆盖后续对手的连锁变化，保留旧结算修订。

升级前已完成且没有积分明细的旧局保留为「未结算积分」，不会自动补算。正式模式需要按顺序应用所需迁移；启用策略及已有真实 MMR 的处理见 [积分启用与历史更正](docs/rating-rollout.md)。累计 PT 包含导入基线及导入后已结算对局的最新单场 PT，不重复累计旧修订，不包含段位、赛季或积分重置。活动和榜单口径见 [活动与排行榜说明](docs/events-and-rankings.md)。

## 项目结构

```text
lib/
  main.dart                  # 环境配置、启动与生命周期
  app.dart                   # 应用入口与导航
  domain/                    # 模型、姓名及计分规则
  application/               # 状态与操作协调、刷新、重试
  data/                      # 仓库接口、本地演示、Supabase 实现
  presentation/              # 主题、组件与页面
supabase/
  migrations/                # 数据库初始化与业务 RPC；部署状态以目标数据库为准
  scripts/                   # 管理员初始化工具
test/                        # 纯本地业务和界面测试
docs/                        # 产品规格、设计参考、配置说明
android/  ios/               # 原生平台工程
web/                         # 开发预览入口
```
